# PhantomGladiator — 《影之刃零》斗蛐蛐 Mod 实验项目

目标是让指定怪物主动交战，并具有原生掉血、受击和死亡反馈。

**当前运行：v0.30-custom-keys。** 八项功能快捷键全部默认未绑定，点击面板键框自定义并保存，冲突显示具体功能/单位；明确保存过的旧设置保留。旧F6/F7/F2/F8不再固定注册，见[快捷键说明](docs/FUNCTION_KEYS.md)。独立BOSS血条及数字、观战收音/隐身/锁血与退出恢复、数值统一和NPC投技均保留。全部866个目录条目开放尝试，每批1–8只、总量不限；不代表全目录兼容或长期稳定性已验证。

独立 Windows 原生 EXE 和界面包装按用户要求暂缓，当前没有可交付的正式 EXE。现有本地面板用于核心功能测试；普通使用不需要看调试窗口，日志核对由助手完成。

**数值统一默认关闭。** 开启后，首只有效NPC的出生生命/杀气上限、攻击/削杀气及攻防倍率作为后续召唤基准；保留招式、体型、速度和AI，全部清场后重取基准。阿花→魔渊两轮均109/109项读回一致，正常消耗、清场重置、血条和交战已验证；不保证所有候选或每招伤害相等。前版属性传递失败引起血条消失/不能开战的问题已修正，完整范围和历史失败见[数值统一记录](docs/STAT_MATCH.md)。

## 本轮如何测试

1. 当前有 **41 个Lua脚本**。更新前用面板退出观战、关闭独立无仇恨并停止清理，等待恢复完成；随后由用户在UE4SS窗口点 **Restart All Mods**。
2. 打开 [当前测试面板](http://127.0.0.1:8765)，等游戏已连接且玩家进入地图。可直接用面板按钮，也可在“快捷键设置”自行录键并保存。
3. 选择单位、队伍与数量（每批1–8，总量不限）。普通持刀“暴徒”仍是已有互伤实测的基准；其它单位可尝试但兼容未保证。机灵鬼的天然无敌/穿透不会因开放召唤而改变。
4. 蓝红各有活跃战斗单位后点“开始交战”或使用自己绑定的键。“暂不配队”有独立存活计数和清理按钮；“停止并清理全部召唤单位”清理本Mod的对象。死亡人数归零不等于尸体已经清理，另看登记/待清理提示。诊断函数挂钩继续关闭。

面板服务已在本机启动；之后需要手动启动时，在仓库根目录运行 `powershell -File .\panel\Run-Panel.ps1`。网页能打开不代表游戏已连接，命令进入队列也不代表已执行；看游戏连接状态和回执。开发阶段热重载才需要操作 UE4SS 窗口。

助手读取 `platform\steam\ue4ss\UE4SS.log`。热重载前先退出观战、关闭无仇恨并清理，确认恢复完成；旧版无快照的残留改动仍需用户自行重载关卡或回标题重进。

## 按键与范围

| 功能 | 默认键位 |
| --- | --- |
| 召唤所选单位 | 未绑定 |
| 开始交战 | 未绑定 |
| 停止并清理 | 未绑定 |
| 刷新单位目录 | 未绑定 |

每张单位卡片和八项功能都可录入键盘按键或Ctrl/Alt/Shift组合；Esc取消，×清空，功能键修改后需保存。主键在功能与单位之间互斥；保存后以游戏读回为准。相机移动仍用WASD、Q/E、Shift及鼠标，设置时请避让游戏自身操作键。面板退出观战按钮始终独立于键位设置。

无仇恨仅请求 NPC 对玩家中立、移除其仇恨中的玩家，并设置玩家 `CanBeHatredNow=false`；关闭时恢复记录。它不改变镜头，也不补造伤害。面板显示开启表示请求状态，仍需观察怪物行为与恢复效果。

v0.18.3起，开战不会另外把玩家设为中立，F8与网页按钮控制同一项功能。网页结合实际玩家资格及待恢复记录显示“已开启”“已关闭”或待确认；恢复过程中不提前显示已关闭。F8关闭后恢复正常敌对资格，正在攻击另一只NPC的怪不一定立刻转向玩家。

当前已核对 **19736条缓存路径、267049条已挂载资产记录**，合并目录929条、过滤已知非单位后面板866条；主图鉴177条，中文/分类精确类映射181条（含别名）。没有原生名称的条目明确使用非官方工作译名。全部目录现在开放尝试，实际能否生成或战斗仍需运行时验证。`uncertain`命令不会自动重放，原生生成返回不明时停止批次，避免重复制造未知对象。

v0.19新增官方章节和地图归属筛选，默认显示177条主图鉴角色，全部674候选另设视图。主图鉴的75条BOSS类记录含形态/变体；普通敌人暂未细分小兵/精英。地图表示原生图鉴归属，不代表全部实际刷新点。字段、统计和验证边界见 [分类依据](docs/CATALOG_CLASSIFICATION.md)。

v0.20已完整核对当前挂载注册表的267049条资产，候选由674补到866，新增主要为玩家、演出和测试角色；当前积累55类单位、3个地图区域的刷怪配置证据。可勾选“有刷怪配置证据”查看，详情会与图鉴归属分开展示。完整结果见 [资产核对报告](docs/ASSET_AUDIT.md)。

物理资源包的目录索引现已解密：310973个文件条目，252284个资源包全部与注册表对应。面板“图鉴范围 → 磁盘单位（已解密）”沿用卡片布局，按章节、地图和小怪/BOSS等类型筛选；原始文件另设入口。已核对852个角色类（含剧情/演出/模板），均与现有目录对应，不是新增852种敌人。未加载地图的资源正文和完整刷怪规则仍待解析。解密方法与工具只保留在作者本地，不随仓库公开。本次只更新面板，无需重载游戏Mod。

## 本地安装与更新

当前开发环境记录为 Steam build 26266538、UE 5.7.4、UE4SS experimental 3.0.1-1185；未验证其他构建。

1. 将 UE4SS 放到游戏本体目录 `PBZ\platform\steam\`，不要放到仅有启动器的目录。
2. 将本地 `GameConfig/` 内容复制到 `platform\steam\ue4ss\`。这里包含本作所需签名和内存布局适配。
3. 将 `Mods/PhantomGladiator/` 复制到 `ue4ss\Mods\`，在 `Mods/mods.txt` 加入 `PhantomGladiator : 1`。
4. 更新前先关闭 F8 无仇恨并等待恢复，再按 F4 等待取消、恢复及参赛者清理结果，最后由用户点 **Restart All Mods**。恢复失败先处理或重试，不要重载丢失账本。

面板与游戏共用的 Runtime 明确为：
`D:\steam\steamapps\common\PBZ\platform\steam\ue4ss\Mods\PhantomGladiator\Runtime`。
里面是资源目录、已知类缓存、快捷键、状态和命令回执文件，不使用游戏工作目录猜相对路径。

日志中的 `loaded` 只表示 Lua 加载完成。F4 只能恢复当前 Lua 生命周期记录的改动，不能追溯 v0.12 的无快照状态；首次迁移仍须由用户重载关卡或回标题重进。

## 开发与证据

先读 [docs/HANDOFF.md](docs/HANDOFF.md)，历史实验与失败记录在 [docs/REVERSE_ENGINEERING.md](docs/REVERSE_ENGINEERING.md)。v0.14 的 F9 空类失败已在一个真实类别上取得复验：`03:00:06`，Vessel Child 路径加载返回 `found=true/loaded=true`，空场景生成两只。这个结果不能推广为所有怪物通过。

旧版清理接受 `K2_DestroyActor` 后 `IsValid` 仍为 true，之后蓝队数归零但旧提示滞后；v0.16 增加销毁状态读回和状态刷新，待实测。`03:05:06` 出现 `Ref was not function` 后心跳停止，游戏进程仍响应；本轮改用稳定游戏线程循环以减少跨线程引用操作，**尚未证明该故障的根因已解决**。

当前离线测试覆盖目录、资源导出、擂台清理、无仇恨恢复、文件桥和面板调度。主程序集成入口是 `tools/test_main_boot.lua`，使用隔离目录加载真实 main 和全部模块，检查空 NPC 条件下的类解析、游戏线程分发及相机按键。命令见 HANDOFF 第 9 节；`tests/test_main_controls.lua` 是 v0.14 历史基线，不再作为当前入口。离线通过不代表游戏战斗通过，也不能证明 UE4SS 的运行时引用问题已修好。

引擎适配参考 [KintaroModding/ue4ss](https://github.com/KintaroModding/ue4ss)，签名与布局的历史核对记录保留在逆向笔记中。禁止提交游戏资源、导出的头文件或崩溃转储；历史记录表明 mapping dump（Ctrl+Num6）会崩溃，不使用该功能。

本项目用于单机离线实验，与 S-GAME 无关联，不分发游戏资源。
